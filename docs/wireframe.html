Wireframe & User Flow

Admin Panel Sistem Informasi Perpustakaan Digital — Universitas Pamulang

Lembar ini adalah keluaran Low-to-Mid Fidelity untuk Milestone 1. Panduan tugas membolehkan wireframe disusun dengan Stitch by Google atau tools HTML/CSS wireframing sejenis; berkas ini memakai jalur kedua sehingga rancangannya hidup di dalam repositori, ikut ter-deploy, dan tetap sinkron ketika tata letaknya berubah.

Warna, bayangan, dan permukaan glass sengaja ditiadakan di sini. Yang diuji pada tahap ini adalah penempatan komponen dan alur kerja, bukan rupa akhirnya — rupa akhir ada di design system dan di file Figma.

1. User flow admin

Alur yang sama dengan Bagian 4 perancangan.md, digambar agar dapat dibaca sekali lihat.

flowchart TD
    A[Login Admin] --> B[Dashboard]
    B --> C{Pilih Tindakan}
    C -->|Kelola koleksi| D[Data Buku]
    C -->|Kelola anggota| E[Data Anggota]
    C -->|Layani transaksi| F[Peminjaman]
    C -->|Rekap| G[Laporan]
    D --> H[Form Tambah/Edit Buku]
    H -->|Validasi lolos| D
    H -->|Validasi gagal| H
    D --> I[Modal Konfirmasi Hapus]
    F --> J[Catat Peminjaman Baru]
    F --> K[Proses Pengembalian]
    K --> L{Melewati jatuh tempo?}
    L -->|Ya| M[Hitung Denda Otomatis]
    L -->|Tidak| N[Selesai]
    M --> N
    G --> O[Cetak Laporan]

Titik keputusan yang menentukan perilaku sistem ada dua: validasi formulir yang menahan pengguna di halaman yang sama saat gagal, dan pemeriksaan jatuh tempo yang memicu perhitungan denda otomatis.

4. Dari wireframe ke layar jadi

Urutannya: lembar ini menetapkan tata letak dan alur, perancangan.md menetapkan struktur data dan aturan bisnis, file Figma menaikkannya ke High-Fidelity, lalu kode menerjemahkannya. Bila tata letak berubah di kode, lembar ini yang diperbarui lebih dulu agar ketiganya tidak saling bertentangan.
